## Tables Created (4 Core + 1 Shared)

### 1. `briefing_sessions` — Aggregate Root

**Purpose:** Parent entity representing a discovery/briefing session with a client
**Rows per session:** 1
**Lifecycle:** IN_PROGRESS → COMPLETED | ABANDONED

| Column | Type | Constraints | Notes |
|--------|------|-----------|-------|
| `id` | UUID | PK | Auto-generated |
| `workspace_id` | UUID | FK→workspaces, NOT NULL | Tenant scoping |
| `client_id` | UUID | NOT NULL | Reference to other bounded context (no FK) |
| `service_type` | VARCHAR(50) | CHECK, NOT NULL | SOCIAL_MEDIA, LANDING_PAGE, etc. |
| `status` | VARCHAR(20) | CHECK, NOT NULL | IN_PROGRESS, COMPLETED, ABANDONED |
| `public_token` | VARCHAR(255) | UNIQUE, NOT NULL | Client access link (no auth required) |
| `completion_score` | INT | CHECK 0-100, nullable | Set only when COMPLETED, must be ≥80 |
| `ai_analysis` | JSONB | nullable | AI summary at completion |
| `abandoned_reason` | VARCHAR(500) | nullable | Why session abandoned |
| `created_at` | TIMESTAMPTZ | NOT NULL | Auto-set on insert |
| `updated_at` | TIMESTAMPTZ | NOT NULL | Auto-set on insert, updated on state change |

**Indexes (8):**
- `idx_briefing_sessions_workspace_id` — Workspace scoping
- `idx_briefing_sessions_status` — Find by status
- `idx_briefing_sessions_client_id` — Find by client
- `idx_briefing_sessions_service_type` — Find by service type
- `idx_briefing_sessions_public_token` — Client access
- `idx_briefing_sessions_created_at` — Timeline queries
- `idx_briefing_sessions_active_single` (PARTIAL) — Enforce invariant: only 1 active per client/service/workspace
- `idx_briefing_sessions_completed_recent` (PARTIAL) — Recent completions for scope generation

**Invariants Enforced:**
- Completion score ≥ 80 only when status = COMPLETED (CHECK constraint)
- Single active briefing per client per service per workspace (PARTIAL UNIQUE INDEX)

## Functions/Procedures (2)

### 1. `update_updated_at_column()`
**Trigger function:** Auto-updates `updated_at` timestamp on every UPDATE to `briefing_sessions`

```sql
CREATE TRIGGER briefing_sessions_update_updated_at
BEFORE UPDATE ON briefing_sessions
FOR EACH ROW
WHEN (OLD.* IS DISTINCT FROM NEW.*)
EXECUTE FUNCTION update_updated_at_column();
```

## Data Flow & Event Publishing

### Briefing Domain Lifecycle → Outbox → Kafka

```
BriefingSession.startNew()
  ├─ Insert into briefing_sessions (status='IN_PROGRESS')
  ├─ Insert questions for service type
  ├─ Insert event to outbox: "briefing.session.started"
  └─ [Activity log: SESSION_STARTED]

Client submits answer
  ├─ Insert into briefing_answers (immutable)
  ├─ AI analyzes answer (if configured)
  ├─ Insert into ai_generations (cost tracking)
  ├─ Check if follow-up needed (AI detection)
  │  └─ If yes: Insert new question + mark follow_up_generated=true
  ├─ Insert event to outbox: "briefing.answer.submitted"
  └─ [Activity log: ANSWER_SUBMITTED]

Client completes briefing
  ├─ Check: progress >= 80%
  ├─ Update briefing_sessions (status='COMPLETED', completion_score=XX)
  ├─ Insert event to outbox: "briefing.completed"
  ├─ [Activity log: SESSION_COMPLETED]
  └─ Kafka: briefing-service publishes to topic "briefing.events.v1"
     └─ proposal-service listens & creates ProposalDraft

Kafka Publishing (Background Worker)
  ├─ Query: SELECT * FROM outbox WHERE published_at IS NULL
  ├─ For each event: publish to Kafka topic
  ├─ Update outbox.published_at = now()
  └─ [Transactional outbox pattern: no events lost]
```

## Performance Tuning Notes

### Query Patterns Optimized

#### 1. Find Next Question for Client
```sql
SELECT * FROM briefing_questions
WHERE briefing_session_id = $1
ORDER BY step
LIMIT 1 OFFSET (answered_count);
-- Uses: idx_briefing_questions_session_id + idx_briefing_questions_step
```

#### 2. Get Session with All Answers
```sql
SELECT bs.*, ba.* FROM briefing_sessions bs
LEFT JOIN briefing_answers ba ON bs.id = ba.briefing_session_id
WHERE bs.workspace_id = $1 AND bs.id = $2;
-- Uses: idx_briefing_sessions_workspace_id + PK
```

#### 3. Check Active Briefing (Invariant)
```sql
SELECT * FROM briefing_sessions
WHERE workspace_id = $1 AND client_id = $2 AND service_type = $3
AND status = 'IN_PROGRESS';
-- Uses: idx_briefing_sessions_active_single (PARTIAL UNIQUE)
```

#### 4. Daily Cost Report
```sql
SELECT * FROM v_ai_generation_costs
WHERE generation_date >= CURRENT_DATE - INTERVAL '30 days'
ORDER BY generation_date DESC;
-- Uses: view + ai_generations indexes
```

### Scaling Considerations

- **Partitioning:** No partitioning needed for MVP; briefing_sessions typically < 1M rows/year
- **Archiving:** After 2 years, move completed sessions to archive table
- **Connection pooling:** PgBouncer if connection count > 100
- **Read replicas:** For analytics queries (v_ai_generation_costs, v_briefing_sessions_active)
